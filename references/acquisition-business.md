# 外贸找客与高意向判断

## 1. 先画出采购链

先回答：产品解决哪个环节的问题，谁制定规格，谁采购，谁付款，谁承担交付风险？不同角色不是同一个“采购经理”。

以光模块为例：项目/网络工程师制定端口、波长、距离与交换机兼容要求；采购执行询价、供货与账期；小集成商老板可能合并这些角色。分销商买的是周转、SKU覆盖、返修与供货稳定；网络集成商买的是项目可用性、BOM匹配和交付风险；终端运营商可能有严格供应商准入。

从你已证明能提供的能力反推适配买家。没有兼容测试、库存/交期事实，就不能以这些承诺吸引客户。不能因为目标公司很大或处于增长行业就判断它适合一个新 SOHO。

## 2. 五条查询路线

| lane | 去哪里找 | 先找什么 | 如何避免误判 |
|---|---|---|---|
| buyer | Google/当地搜索、企业官网、Maps线索、行业协会 | 真正使用/集成/转售该产品的企业 | 目录/地图只提供线索，回官网确认主体/地区/业务 |
| trigger | 企业项目页、新闻、客户案例、技术招聘 | 新建项目、扩建、替换、供应中断窗口 | 新闻不能证明采购开放；招聘只是弱信号 |
| rfq | 买家 RFQ、公开招标、采购公告 | 规格、数量、截止日、买方主体、资格 | 已截止、已授标、与己方规格不符不标当前意向 |
| channel | 品牌伙伴目录、展会/协会名单、经销商目录 | 有客户资源的集成商、分销商与补位机会 | 品牌排他、授权限制、竞品身份需反证检查 |
| ecosystem | 项目中标结果、上下游/配套设备、供应商客户案例 | 谁实际交付项目、谁有长期补货任务 | 终端买方未必直接买零件，可跟到中标集成商 |

V1 程序内置的是 Serper 自然搜索 + Jina 网页读取；其他来源是调查路线，不代表已实现平台专用爬虫。登录/收费/受限数据不可用时记缺口，可导入有来源的企业 seeds，不假装抓到了海关/LinkedIn数据。

## 3. 本地语言、角色和场景交叉搜

只搜“optical transceiver supplier Brazil”容易得到同行。搜索“谁在完成需要它的业务”更有用。

| 路线 | 巴西光模块调查示例 |
|---|---|
| buyer | `Brasil "integrador de redes" "SFP"` |
| buyer | `Brasil "redes corporativas" "fibra óptica" "switch"` |
| trigger | `Brasil "ampliação" "rede" "data center" 2026` |
| rfq | `"transceptor" "10G" "cotação" Brasil` |
| rfq | `"SFP+" "licitação" "aquisição"` |
| channel | `Brasil "distribuidor" "switches" "transceptores"` |
| ecosystem | `"rede óptica" "contratada" "integrador" Brasil` |

这些只是查询模板，不是任何公司需求事实。任务改国家/ICP属于范围变化，新建计划；范围内关键词与顺序可调整。用 buyer 路线取得足够画像样本，再沿每家官网链接找项目、产品/方案、客户案例和联系人。不要对所有企业机械请求不存在的四个固定路径。

第三方公告要识别文中买家、中标商/集成商，再确认其官网；程序若只得到第三方域名，标未确认，通过 seeds 导入正确主体。不要把媒体/招标平台的邮箱当目标买家邮箱。

## 4. 分开 fit、intent、reachability

### 买家匹配 fit

必需：主体、地区、相关业务、购买/集成/转售角色的一手依据。反证包括：只是同行制造商、只装家用模拟监控、规格认证不符、只接受现有品牌/供应商、公司已停业。单纯“有网站/有邮箱/做科技”不足。

### 采购信号 intent

强信号：明确采购请求/招标、替换采购，能定位时间、产品/项目和买方。场景信号：相关项目/扩建、部署/迁移，采购仍需验证。弱信号：产品目录、招聘、行业景气、融资新闻、关注话题。

本版 A/B/C：匹配+近90天一手直接采购信号→A；匹配+近90天项目/扩建→B；只有业务匹配→C。没有日期不硬升；过期招标、授标后的项目不当作“仍在招标”。程序分数只用于排序，绝非真实回复率。

当前结构化规则保守地要求证据中出现 ISO 日期才标 date_grounded；本地日期、公告状态、采购有效性仍应人工核对。即使程序给 A，也不能写“客户已经有购买意向”。真实高意向需通过客户回复和需求确认升级。

### 可达性 reachability

姓名、当前任职、相关职责、来源与邮箱验证分别检查。Treg 给到 valid 邮箱只证明渠道的一部分，不是公司采购意愿。官网联系表单/通用邮箱可作为人工渠道保留；不因此扩展到自动表单或 WhatsApp 群发。

## 5. 光模块的实操画像

| 买家 | 可验证线索 | 首次沟通的低摩擦问题 |
|---|---|---|
| 网络集成商 | 光纤骨干/园区/机房网络项目，交换机和SFP部署 | 是否愿意先比较某个项目的型号/BOM？ |
| 网络设备分销商 | 在售交换机/SFP，多品牌渠道或补货业务 | 当前哪些规格存在补货/供货缺口？ |
| 中小 ISP/MSP | 自建网络、接入/汇聚升级，相关设备证据 | 哪些交换机型号/链路距离需要选型？ |
| 工业/安防集成商 | 大型园区、工厂光纤上联、工业交换机 | 项目的光口标准和测试要求是什么？ |
| 运营商/数据中心 | 真实采购/项目、供应准入和认证要求 | 是否接受该类供应商、由谁负责技术准入？ |

不要笼统把所有安防公司、电信机房和数据中心都算优质客户。优先选与你已有证明能力匹配、采购路径可理解、能小规模验证的群体。以上是首轮验证建议，不是已通过市场实验的国家/行业排名。

## 6. 客户价值 Hook

模板：**客户事实 → 尚待验证的问题 → 已证实的己方能力 → 一个小问题。**

例：官网有园区网络升级案例（事实）；可能需要核对模块选型/替换备货（假设）；我方有具体型号规格和真实测试记录（必须存在的供货事实）；“是否可以先对一两个型号做规格比对？”（低摩擦动作）。

不以“我们是专业厂家，价格最优”开场；不假装客户有问题，不承诺未证实兼容/库存/交期。技术负责人关心可用性和部署风险；采购关心规格、供货与责任边界，文案针对角色调整。

## 7. 首轮业务验证

建议一个产品×一个国家×一个 ICP，从约10家候选开始。人工标记：是否真正买家、证据是否支持、是否近期窗口、联系人是否在职、邮箱验证状态、Hook是否与己方能力匹配。目标数未达保留缺口，不把容易联系的无关企业补进去。

先比较“合格且可达企业数量/总实际成本”和人工审核时间，再观察商务结果。有效回复、正向回复、询价、样品请求、退订和退信分开；分母、观察窗口和已回填比例必须明确。未回填/无数据不能当零回复；本版不自动收件或计算跨市场实验。

## 参考资料（2026-11-05 核对）

- [ITA Find Buyers and Partners](https://www.trade.gov/find-buyers-and-partners)：区分直接买家、代表/合作伙伴，并包含展会等找客路径。其付费服务面向美国企业，这里只借鉴业务方法，不暗示中国 SOHO 可申请。
- [Alibaba RFQ 官方说明](https://supplier.alibaba.com/supplier/rfq.html)：买家主动填写采购信息，卖家按需求报价；不能把平台卖家目录当买家需求。
- [TED 搜索说明](https://ted.europa.eu/en/help/search-browse)：可按采购机会类型、主题、地区与时间搜索；明确区分规划、招标与结果公告。
- [TED API](https://docs.ted.europa.eu/api/latest/search.html)：公开采购数据可供复用；本版没有内置其专用适配器。
